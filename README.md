# Storm Trip — мобильный планировщик поездок

Мобильный веб-интерфейс (PWA) для бэкенда Storm Event. Собирает транспорт, события афиши и отели в один маршрут: пользователь указывает города и даты, получает готовые варианты поездки с ценой и оценкой совместимости.

Приложение выглядит и ведёт себя как мобильное: нижняя навигация, шторка с деталями, безопасные отступы, установка на главный экран Android/iOS. Открывается в браузере телефона, отдельного APK не требует.

## Возможности

- Поиск поездки: откуда, куда, даты, пассажиры, бюджет, сортировка.
- Выбор разделов: поезд, автобус, события, отель.
- Автодополнение городов и станций через `/api/localities`.
- Готовые комбинации «транспорт + событие + отель» и отдельные маршруты.
- Статусы источников: AtlasBus, БЖД, TicketBus, TicketPro, BelHotel; ошибки и пустые ответы видны в отдельной шторке.
- Афиша событий с категориями и поиском; выбранное событие подставляется в маршрут.
- Диалоговый поиск через `/api/chat/json`: «дешевле», «без автобуса», «отель 4★», «только прямые».
- Клиентские фильтры по цене, времени в пути, пересадкам, отелю, событию и прямым рейсам — без повторного запроса.
- История последних 10 поездок в `localStorage`: открытие, удаление и очистка.
- Карточки с бейджами экономии, оценки и скорости, ценой за человека и переходом к источникам.
- «Поделиться» маршрутом (Web Share или буфер обмена) и экспорт в календарь `.ics`.
- Погода в городе прибытия на дату поездки (Open-Meteo) с мягким отказом, если сервис недоступен.
- «Собери выходные»: случайное событие из афиши и готовый маршрут на выходные.
- Голосовой ввод в чате (Web Speech API) и онбординг при первом запуске.
- Тёмная, светлая и системная тема, вибрация, push-уведомления и тестовый сигнал.
- Четыре языка интерфейса: русский, беларуская, English, Polski — с локализованными датами, месяцами и подписями.
- Установка как PWA, кэш оболочки и каталогов, баннер обновления версии.
- Сохранение формы, выбранного события и настроек в `localStorage`.
- Сплэш-экран с логотипом-фургоном при запуске.

### Языки интерфейса

Язык переключается в «Настройки» → «Язык интерфейса»: русский, беларуская, English или Polski. Выбор сохраняется в `localStorage` и применяется до первого рендера, поэтому интерфейс не мигает русским текстом. После переключения страница перезагружается и остаётся на вкладке «Ещё».

Переведены статические подписи и динамические строки: навигация, поиск, календарь, результаты, фильтры, чат, история, афиша, статусы источников и настройки. Даты, месяцы, дни недели, цены и склонения форматируются по выбранной локали. Для беларусской локали месяцы заданы вручную: Chrome отдаёт для `be-BY` русские названия через `Intl`.

## Стек

| Слой | Технологии |
| --- | --- |
| Фронтенд | React 19, Vite 8, чистый CSS, PWA manifest |
| Раздача фронта | nginx 1.27 Alpine |
| Бэкенд | Spring Boot 3, Java 21, H2 in-memory по умолчанию |
| Оркестрация | Docker Compose, два отдельных контейнера |

```text
.
├─ src/                     # Spring Boot бэкенд

│  ├─ src/                  # React-приложение

│  │  ├─ api.js             # Запросы к бэкенду, включая чат
│  │  ├─ i18n.js            # Словарь ru/be/en/pl и перевод DOM
│  │  ├─ history.js         # История поездок в localStorage
│  │  ├─ share.js           # Web Share, буфер обмена, .ics
│  │  ├─ weather.js         # Open-Meteo и кэш прогноза
│  │  ├─ intent.js          # Применение intent из чата к форме
│  │  ├─ voice.js           # Web Speech API
│  │  ├─ haptics.js         # Вибрация
│  │  ├─ format.js          # Даты, цены, подписи
│  │  └─ styles.css         # Мобильная дизайн-система
│  ├─ public/               # manifest.webmanifest, sw.js, иконка
│  ├─ nginx.conf            # SPA + прокси /api -> backend:8080
│  └─ Dockerfile            # Node build + nginx runtime
├─ scripts/demo-phone.ps1   # Запуск демо на Android по USB
├─ scripts/demo-phone.cmd   # Тот же запуск двойным кликом
├─ Dockerfile               # Сборка бэкенда
├─ compose.yaml             # backend + frontend
└─ .env                     # локальные секреты, не коммитится
```

## Быстрый старт

Нужен Docker Desktop с Docker Compose v2.

```powershell
docker compose up --build -d
docker compose ps
```

Открыть в браузере: **http://localhost:3100**

Проверка, что оба контейнера живы и прокси работает:

```powershell
Invoke-WebRequest -UseBasicParsing http://localhost:3100/healthz
Invoke-WebRequest -UseBasicParsing http://localhost:3100/api/event-categories
```

Полезные команды:

```powershell
docker compose logs -f backend frontend
docker compose down
docker compose up -d --build frontend   # пересобрать только фронт
```

### Порты

По умолчанию фронтенд слушает `3100`, бэкенд — только `127.0.0.1:8080` (наружу не выставлен, фронт ходит в него по внутренней сети Docker).

Порт можно переопределить, не меняя файлы:

```powershell
$env:FRONTEND_PORT = "3200"
$env:BACKEND_PORT = "8081"
docker compose up -d
```

После этого фронт будет доступен на `http://localhost:3200`.

## Демонстрация на Android-телефоне по USB

Это основной сценарий: запускаем контейнеры, подключаем телефон кабелем и открываем приложение на нём. Android Studio и сборка APK не нужны — нужен только `adb` из Android Platform Tools. По сути это тот же «Run на устройстве», что в Android Studio, только приложение открывается в Chrome через `adb reverse`.

### 1. Подготовить телефон

1. Настройки → О телефоне → 7 раз нажать «Номер сборки».
2. Настройки → Система → Для разработчиков → включить «Отладка по USB».
3. Подключить телефон кабелем к ноутбуку.
4. На телефоне подтвердить запрос «Разрешить отладку по USB».

### 2. Установить adb (один раз)

```powershell
winget install --id Google.PlatformTools -e
```

После установки открыть новый терминал, чтобы `adb` появился в `PATH`. Проверка:

```powershell
adb devices
```

В списке должно быть устройство со статусом `device`, а не `unauthorized`.

### 3. Запустить демо

Двойной клик по `scripts\demo-phone.cmd` или команда:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\demo-phone.ps1
```

Скрипт:

1. Поднимает `backend` и `frontend` через `docker compose`.
2. Если порт `8080` занят другим контейнером (например, k3d), автоматически выбирает свободный `8091+` для хоста; внутри Docker фронт всё равно ходит на `backend:8080`.
3. Ждёт, пока фронтенд ответит на `/healthz`.
4. Делает `adb reverse tcp:3100 tcp:3100`.
5. Открывает на телефоне `http://localhost:3100`.
6. Если `adb` не найден, печатает инструкцию и адрес для Wi-Fi.

Флаг `-SkipBuild` пропускает пересборку образов (быстрее перед защитой):

```powershell
powershell -ExecutionPolicy Bypass -File scripts\demo-phone.ps1 -SkipBuild
```

Если `adb devices` пуст, проверьте по порядку: включена ли «Отладка по USB», подтверждён ли запрос на телефоне, не выбран ли режим «Только зарядка» в шторке USB. Кабель должен быть data-кабелем, а не charge-only.

На Samsung с One UI 6.1+ (в том числе Android 16) ADB может блокировать **Автоблокировщик** (Auto Blocker): телефон виден как MTP-устройство, но ADB-интерфейс не появляется. Для демо временно выключите его в «Настройки → Безопасность и конфиденциальность → Автоблокировщик»,затем снова включите «Отладку по USB» и переподключите кабель. После демонстрации защиту можно вернуть.

### Вручную, без скрипта

```powershell
docker compose up -d --build
adb devices
adb reverse tcp:3100 tcp:3100
adb shell am start -a android.intent.action.VIEW -d http://localhost:3100
```

`adb reverse` пробрасывает порт телефона на ноутбук, поэтому на телефоне открывается именно `localhost:3100`, а не IP ноутбука.

### Установить как приложение

В Chrome на телефоне: меню → «Добавить на главный экран» / «Установить приложение». После этого Storm Trip открывается с иконки в полноэкранном режиме, как обычное приложение.

### Чек-лист за 5 минут до защиты

1. `docker compose ps` — оба контейнера `healthy`.
2. `adb devices` — телефон в статусе `device`.
3. На телефоне открывается `http://localhost:3100`.
4. Один раз выполнить поиск заранее: первый запрос после старта бэкенда самый долгий (до минуты).
5. Установить PWA на главный экран, чтобы не было адресной строки.
6. Если демонстрация по Wi-Fi — проверить, что телефон и ноутбук в одной сети и брандмауэр пропускает `3100`.

### Вариант без кабеля (Wi-Fi)

Если `adb` нет или телефон не видится:

```powershell
ipconfig
```

Найти IPv4-адрес ноутбука и открыть на телефоне `http://<IPv4>:3100` (телефон и ноутбук в одной сети). При первом запуске Windows может спросить разрешение для брандмауэра — разрешить для частных сетей.

### Почему PWA, а не APK

PWA не требует Android SDK, Gradle и эмулятора: интерфейс обновляется вместе с контейнером, а на телефоне ставится в один клик. Для текущей демонстрации это быстрее и надёжнее. Если в будущем понадобится именно APK, фронтенд можно обернуть через Capacitor, не переписывая интерфейс.

## Разработка без Docker

Бэкенд в контейнере, фронтенд локально с горячей перезагрузкой:

```powershell
docker compose up -d backend
cd frontend
npm install
npm run dev
```

Vite откроет **http://localhost:5173** и проксирует `/api` на `http://localhost:8080`.

Сборка production-версии:

```powershell
cd frontend
npm run build
```

## API, которое использует фронтенд

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/localities?query=Минск&limit=10` | Автодополнение городов и станций |
| `GET` | `/api/event-categories` | Категории афиши |
| `GET` | `/api/events?category=&query=&limit=20` | Лента событий |
| `POST` | `/api/search` | Поиск поездки |
| `POST` | `/api/chat/json` | Диалоговый поиск и уточнения (`message`, `userId`) |
| `GET` | `/actuator/health` | Healthcheck бэкенда |

Пример запроса поиска:

```json
{
  "userId": "00000000-0000-0000-0000-000000000001",
  "from": "Минск",
  "to": "Брест",
  "dateFrom": "2026-11-21",
  "dateTo": "2026-11-22",
  "adults": 1,
  "children": 0,
  "budgetMax": 300,
  "sort": "BEST",
  "domains": ["TRAIN", "BUS", "EVENT", "HOTEL"],
  "directOnly": false,
  "eventCategories": [],
  "minHotelRating": null
}
```

Ответ содержит `intent`, `offers`, `itineraries`, `combinations` и статусы источников `sources`. Полный первый поиск может занимать до минуты: бэкенд синхронно опрашивает внешние источники.

## Особенности и ограничения

- Бэкенд по умолчанию использует H2 in-memory: после перезапуска контейнера данные сбрасываются.
- Источники внешние, поэтому выдача зависит от их доступности. TicketPro сейчас может отдавать 404 на старые страницы категорий — в этом случае «Афиша» показывает пустое состояние, а поиск продолжает работать с остальными источниками.
- PWA кэширует оболочку, категории, города и последнюю афишу: при потере сети приложение открывается, но поиск и чат требуют доступа к бэкенду.
- Первый поиск и уточнение в чате могут занимать до минуты: бэкенд синхронно опрашивает внешние источники. На время запроса показывается прогресс, у чата есть предохранитель на две минуты.
- Уведомления сейчас локальные (браузерные): сигнал приходит по завершении поиска на этом устройстве. Серверные push (Web Push/VAPID) не подключены.
- На iOS уведомления работают только у установленного PWA (iOS 16.4+).
- Выбранное событие и форма хранятся в браузере (`localStorage`), на сервер не отправляются.
- Файл `.env` с ключами не коммитится и не попадает в Docker-образы.

## Git

В репозитории используется простая модель веток:

- `main` — стабильная версия.
- `dev` — интеграционная ветка.
- `feature/mobile-frontend` — мобильный фронтенд, Docker-обвязка и демо-скрипт.

Текущая работа ведётся в `feature/mobile-frontend`:

```powershell
git switch feature/mobile-frontend
git status
git log --oneline --decorate -5
```

Перед слиянием в `dev` стоит прогнать `docker compose up --build -d` и smoke-тест: главный экран, автодополнение, поиск, карточка комбинации, афиша.
